HMH 프로젝트 현황 정리 (작성일: 2026-07-09)
====================================================================
이 파일은 지금까지 구현된 기능, 전체 프로세스 흐름, 알려진 갭(빠진 부분),
앞으로 추가해야 할 기능을 정리한 문서입니다. 코드를 새로 열어보지 않아도
"지금 이 프로젝트가 어디까지 됐는지" 파악할 수 있게 하는 게 목적입니다.
새로운 PC/새 대화에서 이어서 작업할 때 먼저 이 파일부터 읽으면 됩니다.

1. 완료된 기능
--------------------------------------------------------------------

[로그인 / 회원가입]
- 로컬 회원가입, 로그인 (아이디/비밀번호, BCrypt 암호화)                : 완료
- 구글 소셜 로그인 (Spring Security oauth2Login, 서버사이드 흐름)      : 완료
- 카카오 소셜 로그인 (닉네임만 동의, 카카오 고유id로 회원 식별)        : 완료
    - 이메일 동의는 받지 않음. member.email엔 "kakao_{id}@kakao.local" 더미값 저장
    - 비즈 앱 전환/검수 안 받음 (side project라 스킵하기로 결정)
- 네이버 소셜 로그인                                                    : 미완료
    - login.html에 버튼(/oauth2/authorization/naver)만 있고 뒤 연동 없음
- 로그아웃                                                              : 완료
- 마이페이지 버튼                                                       : 미완료 (버튼만 있고 disabled 상태)

[루틴]
- 루틴 등록 (제목/타입/목표수치/일일한도/수행요일/시작일)               : 완료
- 루틴 목록 조회 (routineSetting 페이지)                                : 완료 (조회 전용, 아래 "빠진 기능" 참고)
- 루틴 수정                                                              : 미완료
- 루틴 삭제                                                              : 미완료
- 반복 주기(interval_weeks, 격주/N주)                                   : 미완료 (컬럼만 존재, 로직 없음. 의도적 보류)

[일일 루틴 / 사이클]
- 오늘의 일일 루틴 체크 및 달성 수치 입력 (dailyLog 페이지)             : 완료
- 루틴 현황(이번 주기 진행률) 조회 (routineCycleStatus 페이지)          : 완료 (단, 아래 갭 참고 — 진행률 숫자가 실제로 안 올라감)
- 루틴 수행 히스토리 조회                                                : 완료

[데몬 배치 / 스케줄러]
- 매일 00:00:01(Asia/Seoul) 자동 실행 (DaemonScheduler, cron은
  schedule.properties에서 분리 관리)                                    : 완료
- 어제까지 미완료(TODO) 일일 기록을 FAIL 처리                           : 완료
- 오늘이 수행 요일인 루틴에 대해 일일 기록(daily_log) 생성              : 완료
    - 사이클이 없으면 예외 없이 로그만 남기고 skip
- 매주 월요일(하드코딩)에 새 주간 사이클(routine_cycle) 생성            : 완료
    - 회원별 주 시작 요일(weekStartDay) 반영은 안 함 (의도적 보류)
- 지난 주기 마감 처리 (routine_cycle.status를 DONE/FAIL 등으로 변경)    : 미완료 (아래 갭 참고)
- 데몬 실행 이력 로그 (daemon_log 테이블)                                : 미완료 (테이블 스키마만 있고 코드 연동 없음)

[관리자 페이지]
- 마이페이지 드롭다운에 관리자 전용 메뉴 노출 (role=ADMIN만)            : 완료
- /admin 접근 시 role 체크 (AdminCheckInterceptor)                      : 완료
- 관리자 페이지 실제 내용(데몬 수동 실행, 로그 조회, 회원 목록 등)      : 미완료 (빈 뼈대 페이지만 있음)
- 회원가입 화면에서 admin 권한 부여                                     : 없음 (의도적 — DB에서 직접 UPDATE로 처리하기로 함)

2. 현재 실제 동작하는 전체 프로세스
--------------------------------------------------------------------

[1] 루틴을 등록하면 (routineSetting 페이지)
    → routine 테이블에 저장
    → 시작일이 오늘이거나 과거면, 그 자리에서 1회차 routine_cycle을
      바로 하나 만들어줌 (RoutineApiController.save 안에서 처리)
    → 등록한 오늘이 수행 요일이면, 오늘자 daily_log도 그 자리에서 바로 생성

[2] 매일 자정(00:00:01 KST)에 데몬이 돌면서
    → DaemonRoutineCycleService: 오늘이 월요일이면, 진행 중인 모든 루틴에
      대해 "새 1주일짜리 routine_cycle"을 만듦 (직전 사이클 번호 +1)
    → DaemonDailyLogService:
        - 어제까지 안 끝난(TODO) daily_log를 전부 FAIL로 마감
        - 오늘이 수행 요일인 루틴들에 대해, 그 루틴의 "현재 사이클"을 찾아서
          오늘자 daily_log를 새로 만듦 (사이클이 없으면 만들지 않고 로그만 남김)
    → 실행 순서는 사이클 생성 → 일일기록 생성 순서로 보장됨 (DaemonScheduler가
      한 메서드 안에서 순서대로 호출)

[3] 사용자가 dailyLog 페이지에서 체크박스를 누르면
    → /api/routine/update 호출 → daily_log.status를 DONE/TODO로 변경,
      achieved_value 갱신

[4] routineCycleStatus 페이지에서
    → 진행 중인 사이클들의 routine_cycle.target_value /
      current_achieved_value를 보여줌
    → 과거 daily_log 이력(성공/실패)도 같이 보여줌

★★★ 중요 — 위 흐름에서 실제로 비어있는 연결고리 ★★★
- [3]에서 daily_log를 DONE 처리해도, 그에 대응하는 routine_cycle의
  current_achieved_value가 갱신되는 코드가 어디에도 없습니다.
  즉 사용자 입장에서는 "일일 루틴 체크 → 주간 현황에 자동 반영"이 되어야
  할 것 같지만, 지금은 routine_cycle.current_achieved_value가 생성 시점
  기본값(0)에서 절대 안 바뀝니다. routineCycleStatus 페이지의 진행률이
  항상 0%로 보일 가능성이 높습니다. (직접 실행하여 확인 필요)
- 한 주기가 끝나도(routine_cycle.end_ymd가 지나도) 그 사이클의 status를
  DONE/FAIL 등으로 마감 처리하는 로직이 없습니다. 계속 IN_PROGRESS로
  남아있습니다.

3. 앞으로 필요한 기능 (우선순위는 사용자 판단에 맡김, 순서는 그냥 나열)
--------------------------------------------------------------------

[시급 — 프로세스 구멍]
- daily_log DONE 처리 시 routine_cycle.current_achieved_value 갱신
  (실시간 증감 or 재계산) — 없으면 "루틴 현황" 페이지가 사실상 의미 없음
- 주기 종료 시 routine_cycle.status 마감 처리 (DaemonRoutineCycleService에
  새 사이클 만들기 전에, 지난 사이클을 목표 달성 여부에 따라 DONE/FAIL로
  변경하는 로직 추가 필요)

[루틴 CRUD]
- 루틴 수정 (제목/목표수치/수행요일 등 변경)
- 루틴 삭제 (또는 논리 삭제 — routine.status를 활용)
  → 이미 만들어진 routine_cycle / daily_log와의 관계를 어떻게 처리할지
    (삭제 시 진행 중인 사이클도 종료할지 등) 설계 필요

[로그인/회원]
- 네이버 로그인 (카카오와 비슷한 패턴, common provider 아니므로 provider
  URL 직접 명시 필요)
- 마이페이지 (지금은 버튼만 있고 기능 없음) — 이름/이메일 수정, 회원탈퇴 등
- 비밀번호 찾기/재설정 (로컬 계정용)
- 이메일 중복확인/인증 (지금은 DB unique 제약으로만 막고 있음, 가입 즉시
  통과되는 이메일이 실제 존재하는 주소인지 검증 안 함)

[데몬/관리자]
- daemon_log 테이블에 실제 배치 실행 결과(성공/실패 건수, 에러메시지)
  기록하는 코드 (테이블은 이미 만들어둠, 연동만 안 됨)
- 관리자 페이지에 데몬 수동 실행 버튼, daemon_log 조회 화면
- 관리자 페이지에 회원 목록 / 회원별 루틴 조회 (장기 계획)

[보류 중인 것 — 의도적으로 미루기로 한 것들, 나중에 필요해지면 진행]
- interval_weeks (격주/N주 반복 루틴)
- 회원별 weekStartDay (주 시작 요일 커스텀, 지금은 전체 월요일 고정)
- 회원별 "하루 기준 시각" 설정 (예: 새벽 3시를 하루 시작으로 볼지 등)

[운영/배포]
- application.properties에 DB 비밀번호가 평문으로 커밋돼 있음 — 환경변수나
  별도 시크릿 관리로 옮기는 걸 권장 (OAuth client-id/secret은 이미 환경변수
  방식으로 처리해둠, DB 계정정보만 남은 문제)
- JDK 21 로컬 빌드 확인 필요 (이 문서 작성 시점 기준 아직 정식으로
  ./gradlew build 검증을 못 함 — IDE 실행으로는 동작 확인됨)

4. 참고 — 테이블 구조 관련 메모
--------------------------------------------------------------------
- member.password는 nullable (소셜 로그인 회원은 NULL)
- member.provider: LOCAL / GOOGLE / KAKAO / NAVER(값은 있지만 아직 안 씀)
- routine_cycle.status: 항상 IN_PROGRESS로만 존재 (위 갭 참고)
- daemon_log: 스키마만 존재, 아직 어떤 코드도 이 테이블에 INSERT하지 않음
